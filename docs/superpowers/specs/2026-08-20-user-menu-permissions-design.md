# UX меню и права Telegram-пользователей

## Цель

Разделить интерфейс администратора и обычного пользователя, убрать slash-команды из видимых reply-кнопок и обеспечить доставку сводок каждому одобренному пользователю.

## Интерфейс

Reply-клавиатура администратора содержит текстовые кнопки с эмодзи: `📊 Статус`, `📰 Изменения`, `🔍 Проверить сейчас`, `🧯 Ошибки`, `👥 Пользователи`, `🚫 Игнор категорий`, `⚙️ Настройки`, `ℹ️ Помощь`. Клавиатура обычного пользователя содержит `📰 Последние изменения`, `🚫 Мои категории` и `ℹ️ Помощь`. Старые slash-команды остаются совместимыми при ручном вводе.

Настройки администратора управляют расписанием и отдельным флагом уведомлений. Все опасные действия подтверждаются inline-кнопками; callback-обработчики проверяют admin ID до обращения к данным.

## Права

Администратор определяется точным `telegram_admin_id` и имеет все текущие операционные команды. Одобренный пользователь имеет только `/start`, `/help`, `/changes`, `/my_ignore` и автоматические уведомления. `/status`, `/errors`, `/scan`, `/settings`, `/users`, `/ignore`, `/clear_errors` и callback-действия администратора для обычного пользователя недоступны.

Глобальный админский ignore влияет на сам crawler. Персональный ignore пользователя хранится отдельно и влияет только на его уведомления; документ продолжает сканироваться и архивироваться для остальных.

## Доставка

Получатели сводок — администратор, настроенный chat ID (если отличается) и все `UserAccess.status == approved`. Таблица `event_deliveries` хранит `(event_id, chat_id)` и позволяет помечать событие обработанным только после доставки каждому текущему получателю. Один запуск даёт одному чату одну сводку изменений и одну сводку ошибок.

## Проверка

Тестируются тексты/уникальность кнопок, команды обычных пользователей, запрет admin callback-ов, настройка уведомлений и доставка одного события нескольким чатам без преждевременного `Event.notified`.
