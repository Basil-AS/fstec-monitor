# Интерактивный Telegram-бот и безопасное расписание

## Цель

Сделать Telegram-бота FSTEC Monitor удобным для ежедневного использования и
снизить лишнюю нагрузку на сайт и SSD. Автоматические проверки должны выполняться
не чаще одного раза в сутки по умолчанию, в 12:00 по локальному времени сервера.
Ручная проверка остаётся доступной администратору.

## Архитектура

- Настройки расписания хранятся в SQLite и переживают перезапуск процесса.
- `FSTEC_SCAN_INTERVAL_SECONDS` остаётся начальным значением для новой установки.
- Бот не запускает проверку немедленно после старта; он ждёт рассчитанного времени.
- Telegram-планировщик вычисляет следующий запуск по локальным часам сервера.
- systemd timer задаётся раз в сутки на 12:00 как внешний резервный CLI-запуск.
- Одновременные проверки блокируются существующим `scan_lock`.

Поддерживаемые режимы расписания:

1. Раз в сутки в 12:00 (режим по умолчанию).
2. Раз в сутки в 00:00.
3. Каждые 2 часа (совместимость с прежним режимом).
4. Автозапуск выключен; ручной `/scan` продолжает работать.

## Telegram-интерфейс

Постоянная клавиатура содержит статус, изменения, ручную проверку, настройки,
доступ, ошибки и справку. `/settings` показывает текущий режим и следующий запуск,
а inline-кнопки изменяют режим и возвращают в главное меню.

`/status` дополнительно показывает текущий режим расписания, следующий запуск,
состояние проверки и данные о квоте. Запуск из меню подтверждается коротким
сообщением и не создаёт второй фоновой задачи, если проверка уже идёт.

Неавторизованный пользователь по-прежнему получает только сценарий заявки на
доступ. Команды администратора и callback-кнопки проверяют ID администратора.

## Ошибки и устойчивость

- Ошибки Telegram, сети, БД и фоновой проверки логируются и дают пользователю
  понятное сообщение.
- Настройка расписания не должна запускать сканирование немедленно.
- Неизвестные callback-данные безопасно игнорируются после ответа Telegram.
- При рестарте не должно быть двойного запуска из-за старого таймера.

## Проверка

- Unit-тесты расчёта следующего запуска и форматирования настроек.
- Тесты команд `/start`, `/settings`, callback-переключения, ручного запуска и
  авторизации.
- Проверка конфигурации systemd timer на запуск в 12:00 раз в сутки.
- Полный `pytest`, `ruff check`, компиляция Python-модулей и проверка git diff.
