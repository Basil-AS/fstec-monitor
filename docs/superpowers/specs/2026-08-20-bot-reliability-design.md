# Надёжный Telegram-бот и корректное отслеживание документов

## Цель

Сделать Telegram-бота пригодным для постоянной работы: единый интерфейс без дублирующихся кнопок, уведомления только о полезных изменениях, корректное обнаружение новых и удалённых документов, предсказуемое восстановление после сетевых/хранилищных ошибок и диагностируемые зависания.

## Поведение уведомлений

В личный чат отправляются только события, которые требуют внимания: добавление документа, подтверждённое удаление документа, изменение содержимого HTML, добавление/удаление вложения и содержательное или бинарное изменение вложения. Ответы `304`, одинаковые хеши, изменения только разметки и отдельные повторные попытки не отправляются.

Ошибки сохраняются в журнале и группируются в одну сводку на запуск сканирования по компоненту, URL и типу ошибки. Одна и та же ошибка не создаёт новый Telegram-шум при каждом повторе в рамках одного запуска. Успешно доставленные события помечаются обработанными только после успешного ответа Telegram.

## Жизненный цикл документов

После обхода каталога каждый найденный URL помечается увиденным. Активный документ, отсутствующий в текущем полном обходе, сначала получает один пропуск (`missing_runs`), а удалённым считается после двух последовательных пропусков. Для него создаётся одно событие `document_removed`, документ переводится в неактивное состояние, а возвращение URL снова активирует его и создаёт `document_restored` без ложного `document_added`.

## Telegram UI

Команды, постоянная reply-клавиатура и inline-кнопки строятся из единого набора действий. Администратор получает только один главный набор: статус, изменения, сканирование, ошибки, пользователи, игнор категорий, настройки и помощь. Inline-экраны имеют одинаковые действия «Назад»/«Отмена», а callback-данные проверяются до обращения к БД.

## Устойчивость и диагностика

Сканирование остаётся последовательным на уровне запуска и ограниченным semaphore на документы. Ошибка одного документа или вложения не останавливает остальные. Для фоновой задачи сохраняются состояние и результат; исключение задачи не остаётся незабранным. Long polling Telegram, HTTP-запросы и отправка файлов имеют ограниченные retry/backoff и отдельные таймауты. Логи содержат run id, этап, URL без токенов, длительность и итог; секреты никогда не попадают в URL или сообщение.

## Проверка

Добавляются регрессионные тесты на единый набор кнопок, повторную доставку и дедупликацию ошибок, появление/исчезновение/возвращение документа, обработку исключений фонового сканирования, таймаут long polling и безопасное завершение HTTP-клиентов. Существующие тесты должны проходить вместе с новыми.
